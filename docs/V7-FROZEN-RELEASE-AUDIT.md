# V7 frozen-release coverage and regression audit

## Scope and decision

The user paused remaining lesson development on October 27, 2026 and requested the final coverage audit and regression checks. The freeze contains **169 available lessons: 142 new (SP-001–092 and AU-01–50) plus all 27 inherited G/A/X/K IDs**. SP-093–100 are explicitly deferred, absent from the executable catalog and rejected by the Learn start API. No capstones were authored during this audit.

This validates the existing release within its documented simulation boundaries. It does **not** certify completion of the original 150-new-lesson expansion or full Splunk/Ansible/vendor parity. The original Milestone 10 and all-150 portion of Milestone 11 remain deferred.

## Results

- **1,310 tests passed across 78 files**, with zero failed, skipped or pending assertions, on Vitest 4.1.12. The final run completed in 186.89 seconds with the existing three-worker/30-second test limits unchanged.
- All **852 required acceptance assertions** passed for the 142 new lessons, including all seven pre-freeze advanced automation lessons. The evidence gate also passed and rejected a deliberately missing acceptance result in its negative check.
- Every one of the **27 inherited lessons** opened, saved notes, resumed, reset with a backup and returned to unchanged free practice through the API. Existing manual/workflow completion semantics remain explicit.
- All eight deferred capstones were rejected by the actual Learn start API without mutating the active session.
- Workspace TypeScript checks, ESLint and the production web build passed. The existing bundle-size advisory remains.
- Normal lockfile dry run, resolved dependency validation and the final root/workspace dependency audit passed; zero known advisories remain in the resolved tree.

The [machine-readable release evidence](V7-RELEASE-TEST-EVIDENCE.json) is generated by `npm run audit:release -- /path/to/vitest-results.json`. It requires an actual successful complete Vitest JSON report, rejects failed/skipped/pending assertions, matches each of the 142 available lesson fixtures to **six passed acceptance assertions (852 in total)**, (including older file-qualified reference names resolved to their exact test file and assertion title), and verifies the inherited-lesson persistence checks and deferred-capstone API guard. Test-file existence alone is not accepted as proof.

The six lesson cases cover the supported solution, an incorrect action, false-completion rejection, reset, save/resume/replay and isolation. Passive grading checks also ensure evaluation does not advance operations or manufacture results. Existing lessons retain their inherited workflow/manual completion semantics; their compatibility checks do not retroactively certify new scored outcome behavior.

## Dependency and source checks

The audit found known advisories and updated Vitest to 4.1.12 (including its mocker), Zod to 4.6.7 and ECharts to 6.1.0. The vulnerable tinypool dependency was removed from the resolved tree. Zod record schemas now specify their key type explicitly. The full suite runs on the patched dependency set. `npm ls` reports no dependency problems, the normal lockfile dry run passes and the final workspace/root `npm audit` reports **zero known vulnerabilities**. The lockfile is retained; a fresh full install was not run over the active development server.

Primary advisory references: [Zod](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [Vitest mocker](https://github.com/advisories/GHSA-qxg6-89mg-rqv8), [tinypool](https://github.com/advisories/GHSA-85c8-ppgw-ccpr), [ECharts](https://github.com/advisories/GHSA-fgmj-fm8m-jvvx).

Gitleaks scanned release source and all available local Git history with redaction. Both scans produced **seven reviewed nonsecret matches**: one ternary log-sourcetype expression and six uses of an explicit fictional teaching credential in tests. No real API key or private key was identified in those findings. Installed dependencies, generated output and ignored local learner data are outside the release-source scan. This is a reviewed scanner result, not a guarantee that every possible form of personal data or secret is detectable.

The [sanitized safety review](V7-RELEASE-SAFETY-REVIEW.json) records scanner classifications and resolved dependency versions without raw matched credential content.

Personal attribution remains: inherited documentation contains local home paths, learner defaults/tests contain a first name, source-document provenance includes a name, and existing Git author metadata identifies the local author/machine. These are not API credentials. No history rewrite or identity change was performed. Saved learner notes/labels and the SQLite database remain ignored by Git. No repository was published or pushed during this audit.
